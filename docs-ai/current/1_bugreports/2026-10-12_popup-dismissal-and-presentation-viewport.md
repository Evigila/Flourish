# Popup dismissal and presentation viewport diagnosis

The Colligere language menu used a static details flow on SSR routes and a menu controller on interactive routes. Static flow expanded the header; trigger placement could use a large hover parent; popup cancellation was inconsistent. Flourish now shares the owned menu controller, uses the actual trigger rectangle, and exposes Weak/Strong across owned popup entries. Colligere explicitly selects Weak. Host-specific unreadable selected/disabled language roles are corrected only in Colligere's language-menu-colors scope, because arbitrary user-defined palettes cannot guarantee contrast.

Presentation defaults previously imposed 800px on bands/heroes and 320px on footer content. Bands/heroes now default to one browser viewport minimum and can exceed it; footer content no longer receives a band minimum. Progress discovers only explicit outermost marked bands in the owned main, excludes footer and nested surfaces, retains free scrolling, tracks active sections, and aligns clicked targets below sticky chrome. A single-band homepage still exposes one useful return/alignment target.

Final review identified two asynchronous implicit-dismissal races when ReferenceDropdown/SearchAutocomplete changed Weak to Strong during focus processing, and an ancestor-clipping gap in nested scroll previews. Regression corrections and their final verification will be appended after completion. These findings do not justify claiming a visual browser acceptance that has not been performed.

Native operating-system/browser pickers are outside the owned popup contract; no unsupported Strong property is advertised for them. Existing Dialog Busy/CanClose/Dismissible restrictions are preserved. See [manual acceptance](../popup-presentation-manual-checklist.md) and [dependency inventory](../1_dependency.md) for local candidate prerequisites.

# Anchored popup width and physical edge alignment

Date: 2026-10-21, America/Sao_Paulo (UTC-03:00). Implemented and verified with local candidate **1.4.3-preview.portals.7**. Browser-native first-open painting remains manual acceptance. This follows [the .6 implementation](../1_changelogs/2026-10-21_103624_native-select-state-and-identity-preview-six.md), whose evidence remains historical.

## Diagnosis

ServiceMenu forced 320px; ordinary menus had a 190px minimum and 320px cap, MultiSelectBox its own minimum/cap, native details a control-width minimum, and Reference a 480px/mobile-control cap. These rules competed with content sizing. Split menu Buttons filled a common column but retained ordinary Button centering. Shared menu positioning always used trigger.right minus panel.width, while native select and circuit-owned selections used separate paths.

The native picker combined max-content with an anchor-size minimum and a fixed bottom span-left position area. Its UA stylesheet also supplies an anchor-size minimum. These conflicting sizing/position rules are source evidence for the corrective work; no physical browser reproduction was performed to prove every cause of the reported initial flash. See [HTML select rendering](https://html.spec.whatwg.org/multipage/rendering.html#the-select-element-2) and [CSS area-specific alignment](https://www.w3.org/TR/css-anchor-position-1/#area-specific-alignment).

## Implemented ownership

- Shared positionPopup uses the actual trigger center relative to the viewport midpoint to select physical left/right. It sets data-f-popup-align before measuring and retains viewport clamping, hover/action gaps, vertical flip and available-height scrolling. The prior height priority is retained. Theme copying excludes only the geometric --f-popup-align variable, so a nested popup determines its own edge while inheriting its theme.
- Menus and selection panels use max-content, zero fixed minimum and a viewport width cap. Options occupy a common full-width column and align text/flex content to the panel edge. Search inputs inside a popup fill the option-defined column instead of contributing their default 20-character intrinsic width. Ordinary page Buttons and modal dialog layouts retain their own behavior.
- Native SelectBox remains native. Existing initialization, capture pointerdown/focusin/keydown and resize/scroll synchronize alignment before default opening; no deferred picker width measurement, canvas text measurement, fake select or native selection controller is added. CSS clears the UA inline minimum, chooses bottom span-right/span-left, disables picker geometry animation and retains block flipping/scrolling. Native safe alignment and final drawing remain browser-owned.
- ReferenceDropdown and SearchAutocomplete retain circuit-owned state, selection, focus and dismissal. Their original panels use manual native popovers and only reuse placement; this avoids ancestor overflow clipping. The renderer marks panels as manual popovers, CSS keeps unopened panels hidden, and the bridge positions them while hidden before exposing them. Repeated attachment updates the reference without duplicate listeners. Content replacement, scroll/resize, panel removal and disposal refresh or clean up geometry. Strong/busy/pending outside-dismiss rules continue to request the existing circuit method.
- Gallery's aggregate preview entry adds one translated change item in Portuguese, English and Chinese. No public component parameter or third-party dependency is added. The pure-DOM ActionMenu runner adds an explicit --dom-only option; ordinary browser-enabled verification remains available.

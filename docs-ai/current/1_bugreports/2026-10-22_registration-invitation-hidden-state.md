# Hidden registration feedback rendered over valid access forms

Date: 2026-10-22, America/Sao_Paulo (UTC-03:00). Implementation and local automated verification are complete; the running consumer still requires restart and user acceptance. Final evidence was checked at 2026-10-22T20:16:13Z. The previous portal work was committed as Flourish 07b64e0 and Colligere b4e6e36. This follow-up uses the separate local candidate 1.4.3-preview.portals.10.

## Symptom and root cause

The consumer reported its localized short invalid-invitation Notice immediately after opening a Mailpit registration link, before filling the form or submitting account creation. Register always renders that fixed Notice with hidden. Its fragment protocol sets status.hidden and loading.hidden after validating token format. Design declares Notice display:grid and LoadingState display:flex, while Framework previously protected hidden only in selected shell/dialog contexts. ContentSurface does not supply the shell ancestor, and standalone controls also lacked a guard. Author display styles can override native hidden, as described in the [HTML standard](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute).

The running consumer returned HTTP 200 for Register and both delivered CSS bundles. Its fixed Notice retained hidden, but the served Framework had only the old shell guard and the served Design had grid/flex paint. This is a verified style-contract defect; it does not establish that any particular invitation is valid or expired in the database. The user's message is distinct from the longer backend invalid_link outcome. Consumer runtime evidence, authentication limits and manual flow acceptance are recorded in [its report](C:/Users/RC_Auditoria/source/Repos/Colligere/docs-ai/current/1_bugreports/2026-10-22_registration-invitation-hidden-state.md).

## Implementation

Framework gives ordinary hidden priority over control display paint on controlled roots and their descendants: f-root, f-shell, ContentSurface, NavigationSurface, dialogs and menu panels. Standalone Notice and LoadingState also honor hidden. The scoped display:none!important rule excludes hidden="until-found" case-insensitively; it does not create a global host-element display policy. The old dialog rule is consolidated, while ToggleSection's boolean collapse remains separate. Removing ordinary hidden restores existing component paint and display.

The only production behavior change is in Framework framework.css. There is no new renderer, parameter, dependency, host skin, token controller or invitation validation rule. Gallery's current preview entry documents the fix in its three existing cultures. The consumer retains fragment removal, token validation, form transport and password policy, and consumes the fix through the new local package identity. Existing .9 and older package artifacts are retained.

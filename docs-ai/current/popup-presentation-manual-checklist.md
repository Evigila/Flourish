# Popup and presentation manual acceptance

The source and automated tests cover logic, markup and delivered resources. The following browser and native-window checks remain manual; Computer Use was not used.

- Compare Weak and Strong for ActionMenu (generated actions and SSR child commands), DropdownSurface, SplitButton, MultiSelectBox, ReferenceDropdown, SearchAutocomplete, ServiceMenu, interactive NoticeTrigger, TutorialBoard and Dialog. Weak outside click/Escape/focus leave should cancel. Strong must remain open on those gestures, hover leave and repeated trigger activation; select or use the explicit Done/Close/Cancel action. Preserve disabled/busy restrictions. Multi-select allows several choices before Done. Check wrapper forwarding in ApplicationShell, DataTable, LineChart and NavigationGuard.
- Open language-style/header menus from the actual icon and verify below-trigger placement, narrow width, viewport clamp, resize/scroll repositioning, no header expansion and keyboard access. Check SSR and enhanced navigation separately. Disable JavaScript: button-variant native ActionMenu must remain absolutely positioned below its trigger without changing header height; generic table-row native menus retain their in-flow fallback. Automatic top-layer positioning/dismissal needs enhancement.
- In WPF Gallery, check the owned Dialog, ActionMenu/ServiceMenu, SplitButton, MultiSelectBox, DropdownSurface and NoticeTrigger with mouse/keyboard/automation toggles. Test owner-window sizing, backdrop hit testing, CloseAsync/CanClose/Busy, focus restoration and multi-select completion. Native ComboBox/DatePicker/file dialogs retain native cancellation behavior.
- Test the PresentationProgress Gallery sample's two bands in its scroll preview and on a full document page. A default band should be at least one browser viewport high; longer content scrolls normally. Explicit FullHeight=false/MinHeight retains its requested minimum. Hero creates one target; IncludeInProgress=false opts out.
- Scroll partway between bands, click each tutorial-style segment and verify viewport alignment and active tracking. Hover must not display a title tooltip. Use Tab/Enter, reduced motion, small windows and 200% zoom. Check multiple/nested surfaces, nested scroll clipping, dynamic bands, resize and enhanced navigation cleanup.
- Scroll to the footer and confirm natural content height, no footer target, no additional progress segment and no covered footer actions. Progress stays floating while a band is visible and hides when only the footer remains; no row or gap is added after the footer. A single-band document still has one clickable segment; an empty document has none.
- Use light/dark and custom palette values. Flourish retains configured colors; a consumer needing guaranteed language-menu contrast must scope its own semantic roles, as Colligere does. Check standard menu borders/foreground, selected and disabled states.
- In a fixed ContentSurface with a sole directly contained FullHeight band, check a naturally sized TitleBar and no TitleBar. Short access content fills one viewport without outer scrolling; long forms or 200% zoom scroll within main and keep the final field/submit reachable. The skip link enters that same main. Test a short landscape viewport and verify no header growth when a button-style native menu opens before enhancement. Multi-band DocumentFlow pages and natural footer sizing must retain their existing behavior.

- Compare native SelectBox, StandaloneSelectBox and LanguagePicker with Icon=language/TriggerVariant=Quiet in Framework-only and Design. In supporting browsers the real select has one keyboard focus entry and a 48px icon target; its picker follows content width and native arrows/Enter/Escape/outside cancellation. Classic engines must retain readable full-text selection. Repeat all supported cultures, disabled/pending state, failed preference save and retry.
- Compose ContentSurface.FloatingActions with the standard native language selector and a Quiet native theme form. The sole access band should start at the top, behind the controls, with no header row. Opening/closing the picker must not change the document/main/band height. Check 768px, short windows and 200% zoom; long forms scroll only inside main. Verify theme POST/antiforgery, top-right spacing and the skip link.
- Compare PresentationProgress directly with TutorialBoard's bars, gaps and current emphasis. The navigator must match the actual visible content center, accounting for a scrollbar, and keep readable foreground on Primary/Surface bands. Hover must not expose titles; clicking a partial band must align below actual chrome. Footer-only pages/positions and insufficient space hide it without adding document height.
- In colored ShellHeader chrome, compare an enabled native customized Quiet selector with an ordinary Quiet button. Both triggers should follow chrome foreground while the native picker/options retain their separately configured foreground/background. Check hover, disabled state, light/dark appearance and a scoped contrasting option palette.

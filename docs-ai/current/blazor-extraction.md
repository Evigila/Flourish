# Blazor extraction and current adoption

Status as of 2026-10-04: the former single Blazor library has been split into Framework, Design, Shared and Abstract. Colligere now consumes the extracted components through local project references. This is gradual presentation extraction: business pages, API calls, authorization, session state and draft persistence remain in Colligere. The earlier Figma proposal was abandoned in favor of reusable code and an executable Gallery.

This active document describes the current source. Per-run build, package and browser evidence belongs in append-only `currentproject-changelogs/` records; acceptance beyond those observations is tracked in [blazor-manual-tests.md](blazor-manual-tests.md).

## Projects, packages and dependency direction

All four projects are under `src/Flourish.Blazor/` in full-name subdirectories, target .NET 10 and are configured as separately packable NuGet packages at version prefix 1.1.0. A configured package is not evidence of public-feed publication.

| Project / package | Responsibilities | Direct project dependencies |
| --- | --- | --- |
| `Flourish.Blazor.Shared` / `Arkheide.Flourish.Blazor.Shared` | Immutable navigation/appearance metadata; control, table, selection and grid data contracts; local filter/sort/pagination and mask helpers | `Flourish.Core` |
| `Flourish.Blazor.Abstract` / `Arkheide.Flourish.Blazor.Abstract` | Shell/navigation/layout builders, optional appearance interfaces, `ITablePreferences` and `TableSortPreference` | Shared |
| `Flourish.Blazor.Framework` / `Arkheide.Flourish.Blazor.Framework` | Razor components, Patterns and Primitives; runtime registration; browser interaction JS and functional CSS | Abstract, Shared |
| `Flourish.Blazor.Design` / `Arkheide.Flourish.Blazor.Design` | Optional foundation and skin CSS, `AppearancePalette`, `ThemePalette`, scoped application appearance runtime | Framework, Abstract, Shared |

Framework does not reference Design. None of the four Blazor projects references WPF, WinUI or Colligere. Shared preserves existing Core `ApplicationTheme` and `NotificationSeverity` identities; it does not register Core hosting or desktop services. Core's existing `Microsoft.Extensions.Configuration.Json`, `Microsoft.Extensions.Hosting.Abstractions` and `Microsoft.Extensions.Logging.Abstractions` references remain transitive dependencies. The split adds no direct external PackageReference to the four Blazor projects. Framework and Design use the Razor SDK and `Microsoft.AspNetCore.App` shared framework.

Public namespaces remain `ArkheideSystem.Flourish.Blazor`, `.Abstract`, `.Components`, `.Components.Primitives` and `.Components.Patterns`. Assembly names are `Flourish.Blazor.*`; static asset paths use package IDs rather than assembly names.

The root `Flourish.slnx` contains platform projects and their Galleries. `src/Flourish.Blazor/Flourish.Blazor.slnx` lists the four Blazor projects, Core, Gallery and the console/native fixtures directly. Sub-solutions appear as files in the root's Solutions folder; they are not nested project entries.

## Native Framework and optional Design

A native consumer references Framework and registers `builder.Services.AddFlourishFramework(...)`. `ApplicationLayout` adds the required Framework stylesheet through `HeadContent`; a low-level custom layout that renders `ApplicationShell` directly must load:

```html
<link rel="stylesheet" href="_content/Arkheide.Flourish.Blazor.Framework/framework.css" />
```

`AddFlourish` freezes singleton startup shell options and registers scoped default `ITablePreferences` with `TryAddScoped`. It does not register or resolve `IAppearanceService`. Hosts retain normal ASP.NET `Build`/`Run`, routing and authentication. A consumer can replace table preference storage through the public interface.

Functional CSS is required for hidden/accessibility content, scroll ownership, grids, popup placement, resize hit areas and responsive navigation. `framework.css` includes extracted functional layout CSS and `primitives/native.css`. The native fallback preserves visible mask input text, system-colored popup surfaces, painted relative-size SVGs, disclosure/switch state and named container queries. Native layouts retain structural constraints; they do not promise the fixed density of the Design skin. Removing both stylesheets is not a supported equivalent of native mode.

Design is a separate explicit opt-in:

1. Reference Design in addition to Framework.
2. Call `AddFlourishDesign(appearance => ...)` separately. `IAppearanceBuilder.SetColors`, `SetTheme` and `SetFont` configure startup appearance; the old `IApplicationBuilder.ConfigureAppearance` API is no longer present.
3. Load `_content/Arkheide.Flourish.Blazor.Design/design.css` after `framework.css`.
4. Use `ApplicationLayout` to apply the registered Design theme automatically. Independent subtree themes have been removed by user request.

ApplicationLayout reads the scoped IThemeProvider, subscribes to changes and applies application light/dark/system classes. Design owns one standardized application palette; ThemeScope and its guide are removed. Design's `theme-aliases.css` maps the public tokens to the extracted Primitives and NavigationSurface/ContentSurface role variables, including color-scheme. Host inline role variables retain CSS precedence. `native-overrides.css` restores decorative mask overlays and switch appearance only when Design is loaded.

## Program-configured application shell

`AddFlourishFramework` now exposes `ConfigureTopBar`, `ConfigureNavigation`, `ConfigureLayout` and `SetCommandParser<TParser>`. Top-bar configuration owns the application name, local logo path, command menus and optional left/center/right component types. Navigation explicitly distinguishes route entries, command buttons, secondary route entries and bottom-fixed route/command entries. A primary route always has its own target; the framework no longer infers it from the first secondary item.

Configured component regions store only component types. `DynamicComponent` creates each instance in the current Blazor scope, so singleton startup options never capture a component or scoped service. The configured Core `ICommandParser` is also created per Blazor scope and registers handlers into a scope-owned dispatcher. Two server circuits therefore do not share mutable command handlers or their dependencies.

`ApplicationLayout` owns the default `ApplicationShell`, emits the Framework stylesheet, and consumes the optional `IThemeProvider` registered by Design. This preserves the dependency direction: Framework never references Design. The host retains its standard Router and selects `ApplicationLayout` as the default; custom layouts and the low-level runtime override parameters remain available for advanced applications.

`ApplicationLayout.OwnsDocument` defaults to true. It marks the full-page shell with `data-f-document-shell`; Framework locks the containing html/body scroll and fixes that shell to the viewport so `.f-content-scroll` owns page scrolling. Low-level `ApplicationShell.OwnsDocument` defaults to false. Embedded Gallery previews explicitly use false, retaining their local host bounds without locking the document. Document ownership is functional behavior and does not require Design. This additional correction follows the user's report that the earlier Busy-button containment repair did not eliminate persistent body scrolling; see [document scroll ownership](bugfix-reports/2026-10-04_document-scroll-ownership.md).

ApplicationShell includes the public `SectionNavigator` associated with its content ID. By default it discovers the first H2 of each top-level section owned by that content area, excluding nested demonstrations, extra control headings and native/ARIA modal titles. An outer section outside ContentId does not suppress an embedded navigator's own outline; direct content H2 headings are also supported. Hosts may instead supply explicit `SectionNavigator.Entry` values. Native links retain heading targets and accessible names before enhancement. Browser behavior measures the content's scroll position, displays one dot per section in the existing right gutter without reducing the content track, and marks the current location with a larger dot and accent ring. Hover/focus reveals the actual heading in a bounded tooltip; Escape hides it. Activation scrolls the same content area smoothly unless reduced motion is requested and focuses the target heading. After scrolling/heading compaction settles, at most one immediate correction uses the current sticky-heading height; a one-second deadline bounds its lifetime. Wheel, touch, pointer and keyboard interruption cancel that correction. Mutation/resize observation refreshes dynamic pages; disposal restores owned heading IDs/tabindex and removes timers, listeners and observers.

Appearance state is scoped to a user circuit/client host. Startup navigation/layout options are immutable configuration, not current-user authorization. `SetFont` selects a host-provided CSS stack; it does not download text fonts. Gallery keeps the previously approved Noto Sans / Noto Sans CJK SC stack. Material Symbols is an explicitly authorized, bundled icon-font dependency described below.

A primary landing route may also be one of its own secondary destinations. A secondary landing route can likewise be its own first child. Duplicate siblings and routes shared by different branches or modules remain rejected. Each destination renders its configured icon and label; route selection uses the most specific enabled destination across the tree.

`ISubNavigationBuilder.AddSubNav(label, icon, navTarget, configure, exact, disabled)` accepts another `Action<ISubNavigationBuilder>` for third-level entries. The original overload without a callback, including positional Boolean arguments, remains supported. NavigationItem.Children and ChildItems carry nested metadata. Nested builders freeze after registration, and all levels use the existing application-local route validation.

ApplicationShell renders nested native lists inside the existing secondary rail. An item with its own page and children uses the public SplitButton: a route link and an independent triangle button separated by 3px, each with its own rounded shape. The link opens its configured page and closes the narrow-window navigation; the triangle expands or collapses its children without navigating or closing the rail. Both controls receive the same is-selected state from the current route's ancestry. Expanding an unrelated branch does not select either control, and collapsing the current branch does not remove their selection. Design uses matching foreground/background for the two controls. An item without children remains a route link and has no triangle. Only route links expose aria-current; triangle buttons expose aria-expanded and a unique aria-controls target. Collapsed panels remain in the DOM with hidden. Descendant routing selects its ancestry and opens the matching branch on navigation or direct reload. Ordinary rerenders preserve a manually collapsed branch. Expansion is local to the shell instance; disabled ancestors suppress descendant links, toggles and route matching. Public ExpandNavigationLabel and CollapseNavigationLabel parameters provide the disclosure wording. This separate-link behavior supersedes the previous combined branch button by the user's explicit request.

Framework owns the list/disclosure behavior and native fallback. Navigation labels stay on one line and truncate overflowing text; the full label remains the accessible text and the row's title. Navigation and menu scrollbars are hidden while pointer, touch and keyboard scrolling remain available. Optional Design gives third-level siblings one shared Surface panel using --f-navigation-children-surface and --f-radius-control, with the same horizontal padding as secondary items and no added navigation column. Surface is #FFFFFF in Light mode and #263A30 in Dark/dark System mode; this supersedes the earlier preview-colored panel by the user's later 2026-10-04 correction. In narrow windows, tree navigation stays vertical in a bounded scroll area; the existing navigation toggle can expand it into the existing modal-like rail. The mobile focus loop includes both the route link and its separate triangle button. These user-requested third-level and single-line navigation choices are explicit Flourish extensions to the portable navigation guidance; organization and record identity text still follows the portable wrapping rule. Common standards remain unchanged.

Program-configured top-bar AddMenu entries use ActionMenu.OpenOnHover=true. Mouse entry opens the menu without taking focus; the trigger region and popup meet without a dead gap. Leaving both regions closes the weak popup immediately. Moving between them keeps it open. Keyboard activation, arrow navigation, Escape, focus departure, outside interaction and touch activation remain available. The optional Design layer removes full-height vertical dividers beside the brand/menu regions and keeps the trigger's hover/pressed background inside a 48px rounded button rather than filling the top bar's height. Standalone ActionMenu keeps OpenOnHover=false by default so existing click-driven context menus retain their contract. Consumers can opt into hover through the public parameter; disabled or executing actions cannot open or dispatch again. Primitives.ServiceMenu receives the same inset trigger styling while retaining its own CSS hover/focus behavior. Hidden-scrollbar rules also cover NavigationSurface rails, ServiceMenu views and RowActionMenu panels.

## Gallery page organization

The Framework built-in interactions topic uses a two-column Rectangle UniformGrid with five passive UniformGridItem explanations; its three related destinations and invalid-topic return use standard Underline buttons. Home is primary-only. Its four landing destinations use a Rectangle UniformGrid with explicit Columns=2 and Rows=2; UniformGridButton supplies each title, existing icon, description and route. All other primary destinations expose secondary navigation and render only the selected topic or category:

| Primary destination | Secondary content |
|---|---|
| Framework | Application setup, top bar, navigation, commands, layout, built-in interactions |
| Controls | Actions, inputs, data, overlays, feedback, progress, content, shell/layout; all 77 catalog entries remain represented |
| Foundations | Colors/theme, typography, spacing, radius/shadows, dimensions, icon catalog |
| Examples | Index, form composition, live form, records, record details, composed layout, enum selection, search/list |

Multi-route pages reset optional route parameters before accepting a new ParameterView, so navigating from a child topic back to its landing route cannot retain the old topic. `/appearance` redirects to `/foundations`. These are Gallery demonstration and documentation pages; no consumer-specific page is added to Framework or Design.

Controls retains eight secondary categories, each with a third-level entry for every component in that category. Program declares the complete navigation through explicit nested builder lambdas: AddNav(..., secondary => secondary.AddSubNav(..., third => third.AddSubNav(...))). Navigation configuration uses no catalog loop; each label, icon and route is directly editable at its level, with the same configure-lambda style as AddNav. The page catalog remains responsible for the directory and executable guides. Category routes render a Square UniformGrid directory with one UniformGridButton per component, supplying its short title, category icon and destination, with the full name/purpose available through the title hint and accessible name. This replaces the earlier searchable lightweight directory. /controls/{category}/{sample-key} renders exactly one guide without disclosure wrappers. All 77 components, including UniformGridButton, UniformGridItem, SplitButton, DisplayBoard and SectionNavigator, have independent pages. Each guide has five Section components with H2 headings: introduction, control examples, API, scenario examples and scenario code. The component name appears once as the page's large title, without a duplicate H2 above the guide. Exact category and component routes plus descendant matching keep the selected branch coherent, including actions under /controls/actions/{sample-key}.

Each guide dynamically renders a compiled Razor sample twice, once with Preview=true and once in its default scenario mode. The 77 sample files contain their own imports, models, callbacks and scoped demonstration state. The same files are embedded as resources; displayed source removes only Gallery registration/namespace lines. No separate hand-maintained scenario-code string can drift from the executed example. API parameters use the existing DataTable<ComponentParameter>, with parameter name, type, declaration requirement and description columns. Values are reflected from actual public Parameter properties and include types, enum choices, EditorRequired declarations and usage explanations. The name column cannot be hidden. Sorting, pagination, column configuration and empty-state behavior come from DataTable rather than a separate guide-only HTML table. API snippets use fully qualified Razor tags where namespace aliases are not recognized.

The control examples, scenario examples, API invocation code and scenario code each occupy a complete row using the library's generic DisplayBoard. Its optional Design skin uses Display board: silver gray #E5E8EB in light mode and #31483B in dark mode. Code starts at the upper-left content padding without the former 80px top reserve; consecutive boards and following text/content have 24px spacing without doubling, and the copy action only reserves space at the right of the code. Dotted and Centered default to true; hosts place arbitrary ChildContent inside it. Optional CopyText adds an Elevated icon-only copy action at the top right. On success its content_copy icon becomes check for 1.6 seconds before resetting; failure is reported honestly. The clipboard module is imported only when activated. The guide composes code boards with Dotted=false, Centered=false, CopyText and an encoded CodeBlock child. There is no board-specific Code variant or Text parameter: those earlier modes are superseded by these independent composition options. Layouts and data views retain their necessary width. Framework owns positioning, sizing and clipboard behavior; Design owns colors, pattern and spacing. The guide inherits the surrounding theme without forcing local Dark scopes. The API parameter list follows its code board with 24px spacing. These user-approved display colors replace the former #343a40 Gallery-only boards without modifying common standards. DisplayBoard has one edge-aligned overflow viewport; its content wrapper owns the 24px padding (16px in narrow windows). Direct CodeBlock content does not create another scroll track. A constrained board scrolls within that viewport, while its copy action stays outside it at the upper-right. Optional Design uses 4px scrollbar thumbs, transparent tracks/corners and no native arrow buttons where custom scrollbars are supported; other engines retain the thin fallback. Hidden navigation/menu scrollbars remain hidden. Samples retain actual field labels, example data, state feedback and necessary interaction context. Nested layout demonstrations include local viewport CSS, and the page-level navigation guard is opt-in with an explicit explanation. Framework and Design do not acquire Gallery pages or sample data.

## Page headings and the approved reading scale

Colligere workspace source places parent navigation above the page title: ProductEditor supplies RecordPageHeading at line 17 and CustomerEditor at lines 20 and 24. Both PageHeading and Primitives.RecordPageHeading now use Button with Underline, Href and arrow_back before h1. The return action belongs to the heading's upper-left area and uses the same border-hover and focus styles as any Underline Button; heading-specific CSS only controls its placement.

On 2026-10-04 the user explicitly replaced Flourish's previous responsive reading sizes with five fixed values. This is an approved Flourish-specific exception to docs-ai/common/uiuxdesign.md; the portable common document is unchanged.

| Role | Size | Public Design token |
|---|---|---|
| Large page title | 50px | --f-type-page |
| Semantic H1 | 34px | --f-type-h1 |
| Section H2 | 28px | --f-type-h2 |
| Semantic H3 | 20px | --f-type-h3 |
| Body, labels and ordinary controls | 17px | --f-type-body |

Design exposes f-type-page, f-type-h1, f-type-h2, f-type-h3 and f-type-body classes alongside those tokens. The user's later 2026-10-04 instruction increased the page-title role from 42px to 50px. The latest user instruction reserves 38px exclusively for collapsed page headings. Expanded headings use 50px at every viewport width; actual automatic or explicit compact states use --f-type-page-compact (38px). This state-specific exception has no general typography utility and must not be used for other text. Automatic compaction retains the existing 96px/24px scroll hysteresis; narrow layout alone does not shrink the title. Art display requires an explicit f-type-art class and an approved size of at least 42px. Icon glyph dimensions belong to the icon scale, not these text sizes. The fixed reading scale is supplied by optional Design; Framework-only consumers retain native typography.

## Ordinary buttons and uniform-grid actions

Button retains a content-width, 48px minimum-height design with 17px text. ButtonVariant exposes Filled, Outlined, Danger, Quiet, Underline and Elevated; Primary and Secondary preserve their Filled/Outlined compatibility. Underline uses a hover border instead of text-decoration; Elevated adds a light edge shadow. Disabled and Busy are states, not variants. Icon and Text default empty; Icon with no Text or ChildContent infers the icon-only shape and requires an accessible name. The removed IconOnly parameter is no longer a consumer option. ChildContent remains supported. Href renders a native link; unavailable links lose href, leave the focus order and suppress navigation and callbacks, including href supplied through additional attributes. Text uses flex alignment and a consistent line height, with optional text-box trimming where supported. Busy status is screen-reader-only in Framework and positioned within the button in both native and styled modes, so its absolute layout cannot escape to the shell and add document overflow.

UniformGrid.Shape defaults to Rectangle cells with a preferred 2:1 aspect ratio; content can increase their height to prevent clipping in narrow fixed-column grids. Square uses 1:1. By the user's later 2026-10-04 correction, MaxCellSize defaults to 280px and limits only Square cells; Rectangle stretches within its available width and now exposes MaxCellHeight=260, limiting only its cell height. This later user-approved height limit supersedes the previous unbounded Rectangle behavior. In narrow windows, cells with content grow according to content up to that cap; overflow remains scrollable within the cell instead of being truncated. Automatic tracks wrap into rows. The grid stays within its parent so page gutters do not add horizontal overflow. Nullable Rows/Columns and NarrowColumns provide explicit arrangements; explicit row-only mode intentionally distributes content by columns. UniformGridItem is the passive content cell; UniformGridButton is the interactive cell. Both stack the centered Icon above the 34px semantic H1 Title, followed by the 17px description and optional ChildContent. This replaces the earlier side-by-side heading in both shapes, interactive and passive cells, standalone and inherited appearances. This supersedes the former 28px single-text action-cell presentation. Variant independently selects Filled, Outlined, Danger or Elevated (default); Outline aliases Outlined. Item/Button can inherit that appearance or override it. The older Filled=true shorthand selects Filled.

UniformGridButton composes Button's native element and forwards native Type, Href, Disabled, Busy, BusyLabel, OnClick and additional attributes. Title, Icon, Text and ChildContent use the same internal content renderer as UniformGridItem. Design restores one joined rounded grid container with 1px Border dividers, 16px cell padding and 24px grid block margins; internal cells have no independent corner radius or shadow. This explicitly supersedes the earlier independent-card styling. Standalone cells keep their own rounded skin. Square cells have no forced minimum height; Rectangle cells have no forced minimum above their 260px default maximum; safe centering keeps the beginning of overflowing content reachable. Narrow content cells grow up to that cap rather than collapsing to half their width. Standalone cells use 110px and form-action cells retain their 96px minimum. Directory cells show short names without long supporting descriptions. Busy spinners are positioned in the cell corner so they do not displace the centered title or create overflow. FormActions and UniformGrid apply interactive cell rules only to UniformGridButton. Primitives.FormActionBar retains raw button/link compatibility but excludes ordinary f-button elements from its cell selector. SplitButton is independent of navigation: the host supplies primary Href/OnClick, OnSecondaryClick, Selected and optional Expanded/SecondaryControls. Both actions retain their own native semantics and share selection without coupling it to disclosure state. The 3px split gap remains; the primary half's right corners and disclosure half's left corners are 3px, while the outer corners retain the normal radius in standalone and navigation use.

Button and SplitButton resolve fragment-only Href values against NavigationManager.Uri with its previous fragment removed, preserving the current path and query. UniformGridButton inherits this behavior through Button. Thus a host's root base element does not send an in-page status action to its home page. Routed, relative and external destinations retain their original values; Busy/Disabled links still have no target. Scenario source can keep a reusable #status-id without a Gallery-specific route.

## Self-hosted Material Symbols

The user authorized an external icon font on 2026-10-03 and explicitly requested the newer Material Symbols on 2026-10-04. Framework bundles the official Material Symbols Outlined variable WOFF2 and its 4299-name codepoint map from [Google's Material Design repository](https://github.com/google/material-design-icons/tree/737e3324305806514d7909874fa1818ae1808232/variablefont), pinned to revision `737e3324305806514d7909874fa1818ae1808232`. The font is 4003088 bytes and uses Apache-2.0; the Framework package declares `MIT AND Apache-2.0`. The original license and pinned source/hash metadata ship beside the font. There is no runtime Google CDN request or new NuGet/npm reference. A cold load transfers the full approximately 4MB variable font; browser caching should reuse it on later navigation and reloads, which remains a manual timing check.

The font exposes FILL 0–1, wght 100–700, GRAD -50–200 and opsz 20–48. Framework's default settings are FILL=0, wght=400, GRAD=0 and opsz=24. The asset is `wwwroot/icons/material/MaterialSymbolsOutlined.woff2` with SHA-256 `96c9913f4d415adeefcc3fa13f4f75912648f6f426be8b50e5e20c035b17cdf3`; the embedded `Icons/MaterialSymbolsOutlined.codepoints` is 79338 bytes with SHA-256 `225bd09137103cb7746bc93dc08d08764c9f0c3bd04f4b958d4a3c3c19432dd6`. The old classic OTF and codepoint map are removed.

`Icon` renders a mapped Unicode glyph, inherits currentColor, and remains decorative with aria-hidden. Icon-only actions need a name on the enclosing control. Public `IconCatalog.Names` lists official names and `Contains` accepts official names or supported legacy aliases. Unknown names render help_outline. `AppIcon` and `Glyph` delegate to the same implementation while preserving their existing name/size APIs. Supported compatibility aliases remain available. The new catalog does not promise every classic official name: 81 names in the earlier 2195-name map are absent from this pinned Symbols map, and no existing Framework/Gallery source references those names. Framework owns the font and required CSS so the native consumer works without Design; Design only sets size roles and appearance.

This user-authorized choice replaces the SVG implementation for these three reusable icon components. Other functional SVGs remain supported. Flourish applies the portable SVG color and sizing rules to these font glyphs as well; the common contract is unchanged. The icon directory at `/foundations/icons` provides search, incremental display and usage snippets.

The user's subsequent request explicitly enlarges icon defaults in Flourish: standard 26px, primary navigation 24px, tools 26px and search/information 22px. Design exposes --f-icon-default-size, --f-icon-primary-size, --f-icon-tool-size and --f-icon-information-size; Framework-only icons fall back to 26px. Click targets and logo sizing remain separate. These approved Flourish glyph defaults supersede the portable 20.3/23/19px values for this implementation without editing common standards.

## Catalog parameter defaults and sample scope

Every guide's shared DataTable includes a Default value column. ComponentEntry retains all public own/inherited Parameter metadata. Gallery reads initialized auto-property backing fields from fresh reviewed Framework components without service injection, renderer attachment or lifecycle execution. Boolean, numeric, enum, string, empty collection and known initialized text contracts are displayed; missing values, callbacks, templates and type-dependent generic values remain blank. Empty strings are explicit double quotes, not an absent default. The catalog currently has 78 components, 542 API rows and 254 documented defaults; CatalogChecks verifies coverage and representative defaults.

Shape belongs to UniformGrid, not UniformGridButton or UniformGridItem. Those two guides additionally list qualified UniformGrid.Shape, Columns, Rows, NarrowColumns, MaxCellSize, MaxCellHeight, IconSupport, Variant and Filled rows with explicit container ownership. UniformGridButton also describes the alternative FormActions.Columns configuration. This is documentation of existing composition, not a new child-component Shape property. SearchAutocomplete.FilterItems is a boolean switch for built-in filtering, not a function.

UniformGridButton Preview contains two six-cell grids: default Rectangle and Square. Columns=6 and NarrowColumns=2 keep desktop columns explicit and narrow previews readable. Scenario mode uses default Rectangle with working save/reset callbacks and inline status text. Inert status fragment actions were removed from Button, UniformGrid and UniformGridButton; SplitButton's duplicate preview link to an absent scenario target was removed. Real navigation demonstrations remain available.

Ordinary ActionMenu icon and labeled triggers share the standard 48px target height. DataTable's row/card operation context supplies the existing 36px dense-height role to both trigger shapes. Popup behavior is unchanged. Document-owning shells now use overflow:clip rather than hidden: native fragment navigation and scrollIntoView cannot scroll the chrome container. Content scroll remains independent; embedded shells do not receive this document-level rule. See [fragment ancestor scroll](bugfix-reports/2026-10-04_fragment-ancestor-scroll.md) for reproduced evidence.

## Public component layers

| Layer | Current API and role | Consumer boundary |
| --- | --- | --- |
| `.Components` | `ApplicationShell`/`ApplicationLayout`, `PageHeading`/`PageBody`/`Section`, forms and InputBase controls, notices/progress, facts/identity, local `DataTable`, `ActionMenu`, `Dialog`/`BottomSheet` | Models, validation, event callbacks and navigation data remain host-supplied |
| `.Components.Primitives` | Extracted presentation components including `ShellHeader`, `ServiceMenu`, `PrimaryNavigationItem`, headings/page contents, forms/action grids, identity/facts, mask/select controls, `DataTable`, `RowActionMenu`, `NavigationGuard`, `InteractionBoundary` and `EditingGrid` | No Colligere DTO, API client, authoritative session tracker or permission service is required |
| `.Components.Patterns` | `NavigationSurface`, `ContentSurface`, `RecordListPage` | Compose public render slots while the host supplies routes, approved navigation, status and page content |

Some names exist in both Components and Primitives, including DataTable, PageHeading, BottomSheet, ToggleSwitch and UniformGrid. Consumers importing both namespaces should qualify the desired component. Their contracts are not interchangeable: for example the Components Dialog/BottomSheet supports `CanClose`, while the extracted Primitives BottomSheet exposes `IsBusy` and `OnClose`.

`ApplicationShell` owns its title/navigation/content tracks and accepts runtime `NavigationGroups`, `ApplicationTitle`, `TitleBarBrand` and `TitleBarStart`. Hosts must filter runtime navigation according to their authorization; the library does not grant access.

`NavigationSurface` owns the extracted primary/secondary rails and one application-stage scroll track. Its TitleBar, PrimaryNavigation, SecondaryNavigation and ChildContent slots receive host content; ShowSecondary, DocumentKey, ContentId, ContentClass and labels control presentation. `ContentSurface` provides a content track without navigation rails. Both require only browser JS, expose CSS class/style hooks and do not inject appearance services. `RecordListPage` composes heading/actions/status and a titled content section.

The Components `DataTable<T>` uses `TableColumn<T>` value/format delegates and `RowAction<T>` callbacks. It processes supplied local items with all/single-column search, locale/typed stable sorting, null-last ordering, 10-item default pagination, column visibility, list/cards and pointer/keyboard width control. The page-size selector offers 10, 20, 50 and 100 plus a host-supplied custom current value; changing it resets to page one and invokes PageSizeChanged. Loading/error/empty states do not invent records. Row opening is explicit through `OnRowOpen`.

Pager controls are previous, next, then current page/total. Gallery labels counts with the neutral Chinese term 项; the library's English default remains Items. DataTable's display selector and ActionMenu use the same f-dropdown-panel/f-dropdown-item Design rules, with a selected state for visible columns. Sortable column titles use a Quiet Button; hover adds an accent border only around the inner title label while the header cell remains transparent. Popup items have transparent idle backgrounds, including selected rows; pointer hover and keyboard focus supply the shared highlight. Automatic widths cap ordinary data columns at 320px; the last visible data column is exempt, independent of action/spacer columns.

## Cause and ownership

The customized SelectBox is still a native select whose first button child is inert under the [HTML button contract](https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element). Its child cannot be used as the independent source of pointer interaction. The [Chrome customizable-select documentation](https://developer.chrome.com/blog/a-customizable-select) describes the native picker parts made available by base-select. No custom selection controller or LanguagePicker Strength parameter is introduced.

Design's generic select hover and its later customized-select transparent reset both had specificity (0,3,0). The later reset won on the actual select, while the inert child could not supply the Button hover state. This caused missing hover feedback. Separate legacy raw-select picker/option rules also overrode canonical popup radius, shadow and row geometry. The consumer's old language-menu-colors skin independently remapped ten roles; the coordinating task removes that host skin in Colligere. The [consumer diagnosis](C:/Users/RC_Auditoria/source/Repos/Colligere/docs-ai/current/1_bugreports/2026-10-21_service-login-controls-and-language-menu.md) records that integration.

## Implemented contract

The existing standard Button state declaration blocks now also accept native customized-select owner selectors. The real select's hover/open, active, focus-visible and unavailable states project onto its inert trigger. Primary, Secondary, Quiet, Danger, Underline and Elevated keep their own variants, Primary access/footer context and chrome context. Open uses preview feedback; active uses click feedback. Ordinary Button state selectors and declarations remain the shared source. The parent select's duplicate focus outline is suppressed only when its standard trigger receives the same focus ring.

Shell Quiet availability is explicitly split between ordinary buttons and native-owned triggers. A parent-only aria-disabled=true must win even when the inert child has no disabled attribute. The owner branch checks actual select availability; the ordinary branch excludes only f-select-trigger and keeps its original availability checks. This resolves the equal-specificity inherited-color conflict without adding an artificial priority override.

Native ::picker(select) now shares menu Surface/Text/Border, 16px panel radius, popup shadow, 40px minimum option rows, 8px/10px option padding and 10px option radius. Selected options remain selections; they are not painted or disabled as unavailable options. Native selection/value/change/keyboard behavior and culture saving remain untouched. Legacy raw-select styles exclude .f-select so noncomponent raw controls keep their prior path. Browser-owned dismissal remains distinct from ServiceMenu/ActionMenu's existing Strength policy. ServiceMenu's trigger consumes the same standard control radius token.

Sidebar's navigation and details both use --f-surface. Geometry, borders and existing standard ActiveVariant behavior remain. No host palette override is required.

LogoDisplayer adds optional int? LogoSize. Omitted values retain 96px artistic and 48px Compact defaults, including Compact's 32px short-height fallback. A positive explicit value sets the actual image width/height and the supported image-local --f-logo-size variable; it does not change title/context scale, leak to another instance or shrink an explicitly sized image on short screens. Zero and negative values throw ArgumentOutOfRangeException. Compact=true with LogoSize=96 gives a simple horizontal identity with the ordinary 96px image. The Gallery's real access scene and component sample demonstrate this composition; its LanguagePicker sample uses the real icon-only Quiet trigger. Three-language usage, parameter, sample and aggregate preview ChangeLog metadata are updated.

# Keep page headings in flow and slide a separate title into view

2026-11-09 13:45:49 · America/Sao_Paulo · UTC−03:00.

The previous shell algorithm toggled data-compact-heading using scrollTop thresholds. Design kept the same header sticky and changed its height, padding and title size; short content could lose scroll range and required a restoration guard. The default header now stays relative and naturally sized. The old exported update/reset names only clear a legacy attribute, and shell/surface lifecycle no longer installs the obsolete heading scroll listener or animation frame.

PageHeading renders one additional fixed, zero-height frame containing only its title text. It is aria-hidden and inert, contains no second h1, ID, parent link, action fragment or focusable control, and is hidden before enhancement. The original controls remain available when the user returns to the original heading. Explicit Compact does not render the automatic overlay and preserves its compact geometry. DocumentFlow does not enhance the overlay.

The new Framework patterns/page-heading.js observes current heading and ancestor geometry. The whole original heading must cross the actual visible upper edge, after intersection with nested scroll/clipping ancestors and the visual viewport. Returning across that same edge reverses the independent panel transition. No original dimensions or scroll positions change. The measured frame origin supports translated fixed containing blocks; each scroll region owns one page title. Hidden, empty, removed and replaced headings release their geometry, and the last removal releases document/viewport events, observers and pending work. Existing SSR startup discovers the module without requiring component after-render.

Framework supplies Canvas/CanvasText paint, fixed clipping and a 180ms vertical transition only when motion is permitted; Design uses the shared canvas/text/border and compact-title tokens. Entry/exit affects only the decorative panel. Parent/actions and loading semantics remain on the original header. SectionNavigator's separately verified adjustment uses the visible panel's real rectangle for anchors and navigation bounds; see [navigation verification](2026-11-09_134600_section-navigator-heading-overlay.md).

After removing the obsolete listeners and adding Framework paint, the targeted run passed 37 Node cases, including the SectionNavigator script with 31 internal checks and all 19 FloatingNotice cases. These checks cover the exact boundary, unchanged short-page range, nested clips and translated origins, viewport/header resize, independent roots, exclusions, route replacement/disposal, markup semantics, motion CSS and SSR bootstrap. Component render regression checks were updated; compiled/package verification is coordinated separately.
